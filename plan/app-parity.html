How these numbers were produced

Route counts come from asking WordPress itself — rest_get_server()->get_routes() with both plugins active — not from counting register_rest_route calls, which undercounts because one call can carry several methods. The app's side is every client.<verb>() literal in api/, normalised and matched against those routes. All 87 call sites matched a real route with a method that exists, so the app currently calls nothing that isn't there.

183 has not moved this session, and that is correct. Account deletion added DELETE to the existing /me path rather than creating a new path. Counting paths hides that; counting distinct path+method pairs (260) shows it. Both are quoted above so neither number can be mistaken for the whole story.

Only the last band is a problem. The 25 owner routes are moderation queues, commission rules, the audit log, white-label and payout runs — a member's phone has no business calling them. The 12 payment routes are skipped deliberately: the app opens the marketplace's own checkout rather than embedding a card form, which is also what keeps it outside In-App Purchase. The remaining 12 are duplicate paths the app reaches under another name, the namespace index, the batch endpoint, and three web-dashboard-only routes.

A correction to an earlier summary. I previously reported that a buyer “can open a dispute” from the app. That is wrong. The app fetches the site's dispute reasons and can read and respond to an existing case, but POST /orders/{id}/dispute is never called — so a dispute can still only be started on the web. The reasons work shipped the vocabulary correctly; the create flow was never wired.

What has never been verified

Stated plainly, because an unverified thing and a working thing look identical in a table. No run on a real device. No run on a localised site — which is the entire point of the status-label and vocabulary work. No run on the EDD, FluentCart or SureCart rails, where four features are supposed to disappear from the app. No dark-mode pass. What verification has happened is browser rendering at 390px against a seeded local site, plus route-level checks.

Measured against the running plugins on a local site with Free and Pro both active. Counts will differ where different plugins are enabled — the four wpss-pro/v1 cart-adapter routes only exist when SureCart or FluentCart is installed, and were not counted here.
