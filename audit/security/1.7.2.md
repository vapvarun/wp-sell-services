# Security audit — WP Sell Services 1.7.2 (free + pro)

Date: 2026-09-23 · Reviewer: release Gate G · Baseline: `v1.7.2` tag (the
previous cut of this same version line; 43 shipped-code commits since).

**Outcome: no blocker.** The delta against the baseline is zero new findings in
Free and zero in Pro. Nothing in this release adds an unauthorised read or
write, a new input surface, or an unprepared query.

### The 7 CRITICALs, each triaged

All seven are `wp_ajax_nopriv_` handlers, all pre-existing, all carrying a nonce
and a written reason in `audit/admin-action-authority.json`. A public
marketplace has to serve signed-out visitors; the question is what each one
exposes.

| Handler | Why anonymous is correct |
|---|---|
| `wpss_public_signup` | The signup form itself. Gated on `users_can_register` and rate limited 20/hour per IP since Basecamp 10321653411 — before that it honoured neither. |
| `wpss_checkout_create_account` | Account-at-checkout. Gated on the owner's `wpss_checkout_creates_accounts()` switch, rate limited 20/hour per IP. |
| `wpss_live_search` | Public catalogue search — the same data `GET /search` already serves anonymously. Rate limited. |
| `wpss_load_services` | Public catalogue pagination. |
| `wpss_load_reviews` | Public review pagination on a public service page. |
| `wpss_mark_review_helpful` | A helpful vote from a signed-out reader. Writes a counter only, never member data. Rate limited. |
| `wpss_add_service_to_cart` | A signed-out visitor builds a session cart before registering — the normal marketplace flow. Per-session, carries no other member's data. |

**None returns another member's data, and none performs a state change outside
its own session or a counter.**

|---|---|---|---|
| Route authority | `audit/route-authority.json` (178) | `RouteAuthorityTest` | pass |
| Capability map | `audit/capability-map.json` | `CapabilityMapTest` | pass |
| Render authority | `audit/render-authority.json` (19 shortcodes, 6 blocks) | `RenderSurfaceAuthorityTest` | pass |
| Admin action authority | `audit/admin-action-authority.json` | `AdminActionAuthorityTest` | pass |

Pro carries route-authority over its own manifest (7 checks). Its remaining
three guards are scheduled for 1.7.3 on Basecamp 10330518132; its admin-action
manifest declares 5 handlers, all nonce-checked, none anonymous, so what is
deferred is the test rather than an unreviewed surface.

### Found and fixed by these guards during this cycle

* **`AdminActionAuthorityTest` read handler source with comments intact**, so a
  commented-out `check_ajax_referer()` still satisfied the nonce search. Proven
  by commenting out the real check at `AjaxHandlers.php:234` and watching the
  guard stay green on a genuinely CSRF-unprotected handler. Now strips
  `T_COMMENT`/`T_DOC_COMMENT` via `token_get_all()` and requires a call boundary
  so a wrapper cannot satisfy it. (Trap 1 and Trap 3 of the standard.)
* **Three payment routes had never been declared** — `GET /payments/methods`,
  `POST /payments/create-intent`, `POST /payments/confirm`. Not stale:
  *undeclared*. `PaymentController` registers nothing off the standalone rail,
  and the machine the manifests were generated on runs `auto`, so the money
  surface was invisible to the one gate that asks who may reach it. Now declared
  from source: all three behind `RestController::check_permissions` (401 signed
  out), audience `member`.
* **Free's manifests declared Pro's surfaces** — two analytics routes, two
  subscription-plan routes and the `wpss_currency_switcher` shortcode. Anyone
  reading Free's manifest to judge the free plugin's attack surface was reading
  things not in it. Removed.

## G3 — Reviewed diff since the baseline

43 shipped-code commits, 35 files, +1722/-336 in `src/`.

* **New superglobal reads: 0.** The diff introduces no new input surface.
* **New `$wpdb` statements: 2**, both through `prepare()`, plus one literal
  `$wpdb->query( 'ROLLBACK' )`. No request data reaches SQL unprepared.
* Security-relevant files touched: the cart, earnings, orders and services
  controllers, both checkout paths, the Stripe gateway, the service metabox,
  `functions/files.php` and `functions/money.php`.

### The money-path changes, reviewed

* **Add-on index `"0"` was dropped from the charge.** `"0"` is falsy in PHP, so
  three truthiness guards — including `wpss_resolve_checkout_addons()`, the
  canonical resolver every gateway calls — treated "the first add-on" as "no
  add-ons". A buyer who selected only the first add-on was **billed without it**
  and the vendor lost the revenue. Under-charge, never over-charge, and silent
  in both directions. Fixed; regression test asserts the resolved money for
  every selection shape, mutation-proven.
* **Cart accepted a deleted or paused service.** `add_to_cart()` validated;
  `get_cart()` never re-validated, and ten call sites read the cart directly.
  Evidence: `order #583 service_id=1604 total=0.000 status=pending_requirements`
  for a service that no longer existed. Not a disclosure — no other member's
  data is reachable — but it creates an unfulfillable order a vendor cannot
  clear. Fixed in one reader that the money paths call.
* **`ServiceManager::create()` ignored the publish checklist**, so a
  programmatic caller could put a live, purchasable, incomplete listing into an
  owner's catalogue. Held as a draft instead; a filter lets a seeder opt out
  deliberately.

No authorisation change in the diff. No capability check was added, removed or
loosened.

## Scanner-visible but safe — do not re-litigate

Recorded so the next reviewer, human or AI, does not investigate these again.

| Pattern | Count | Why it is safe |
|---|---:|---|
| `sql-direct-interpolated` | 27 free / 13 pro | Interpolated **table names** (`{$wpdb->prefix}wpss_*`), never request data. Values go through `prepare()`. |
| `files-superglobal` | 22 | Upload handling routed through `wpss_store_order_file()`, which validates server-side. |
| `nonce-only-auth` | 104 | Flags handlers whose *line* shows only a nonce. Ownership is checked in the service layer the handler delegates to; the admin-action manifest records which, and `AdminActionAuthorityTest` asserts it. |
| `extract-call` | 5 | Template variable injection in `wpss_get_template()`, keys controlled by the caller, never by request data. |
| `no-abspath-guard` | 6 | Files never reachable by URL (test fixtures and build scripts outside the shipped tree). |
| `esc-sql-on-nonscalar` | 1 | Pre-existing, on a scalar in practice. Carded, not a blocker. |

## Still outstanding at the time of writing

* **G4 — WP Vanguard scan** against a site running the release candidate: not
  yet run.
* **Plugin Check on the built zip** (§7.5) and the **pristine Docker install
  test** (§8): not yet run; both are release blockers and the zip is not built.
* AES-256-GCM migration for `wpss_encrypt_secret()` — Basecamp 10322374784,
  triaged P3 and parked. CBC without a MAC is unauthenticated, but the decrypt
  path returns unprefixed input verbatim, so an attacker able to tamper with the
  ciphertext can already write plaintext; and no caller accepts caller-supplied
  ciphertext, so there is no padding oracle. Confidentiality against a leaked
  database — the threat this defends — is intact.
