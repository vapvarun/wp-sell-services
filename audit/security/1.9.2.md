# Security review - 1.9.2 (Free and Pro)

Reviewed 2026-11-04 against v1.9.1. Blocking findings: none. Four LOW notes, none reachable by a buyer or vendor.

## G1 mechanical sweep (`security-sweep.sh --baseline v1.9.1`)

No category grew in either plugin. Free `ajax-nopriv` went from 6 to 5 (the unused `wpss_live_search` action was removed with its caller) and `nonce-only-auth` from 96 to 95. Pro `nonce-only-auth` went from 9 to 6 (test gateway and test email actions removed). The five remaining `wp_ajax_nopriv_` handlers are the public search, cart and checkout entry points triaged in `1.8.0.md` and `1.9.0.md`.

## G2 authorisation

- `RouteAuthorityTest` passes in both plugins: every live route declares its audience, no manifest entry is dead, public routes say why, and public object routes do not serve unpublished services. Pro also refuses anonymous callers on guarded routes.
- One route was added: `POST /wpss/v1/orders/{id}/mark-paid`, declared `admin`. Dispatched with a valid body against an unpaid order: its buyer and its vendor get 403 `wpss_not_admin`, a logged-out caller gets 401, and the order stayed unpaid.
- `wppqa_probe_roles` as guest, buyer, vendor and admin (1,604 requests): no non-admin role got a 2xx on any write, and no admin write succeeded with the empty body, so nothing changed on the site. The probe does not fill path ids, so it measures role gates only; ownership is covered by the route authority test and the money-route tests in the guard suite.
- REST reachability: 189 routes, every one has a permission callback, no GET answers 5xx.

## G3 reviewed diff

| Surface | Result |
|---|---|
| Manual settle (`mark-paid`, Mark as Paid, `OfflineGateway::settle_manually`) | Admin only. `StandaloneOrderProvider::mark_as_paid()` updates `WHERE id AND payment_status = <old>` and refuses paid, refunded and cancelled orders, so two calls at once fire the paid hooks once. |
| Withdrawals (`EarningsService::write_withdrawal`) | Minimum, balance and the one-open-request rule (pending or approved) are checked under the lock; a negative amount is below any minimum. |
| PayPal batches (`PayoutsBatchService`) | Money in an unfinished batch is reserved through `wpss_vendor_reserved_payouts`. A batch starts only from an admin action, so a vendor cannot use the gap between the batch lock and the withdrawal lock. |
| Store pay-orders (`WCPayOrderResolver`) | `refuse_unpayable_wc_order` only turns `needs_payment` off; `cancel_superseded_wc_order` only cancels pending or failed store orders. |
| Offline "how to pay" email | Claimed with one conditional `JSON_SET` on a fixed path; only `%d` is bound. |
| Secret constants (`security.php`) | The constant is injected through `option_` and `default_option_`; the settings field renders a disabled empty input, covered fields are blanked before save, none of these options has `show_in_rest`, and the browser only receives the Stripe publishable key. |
| Pro exchange rates (`RateService`) | Fixed `https://openexchangerates.org` endpoint, url-encoded `app_id`; not SSRF. |
| Pro subscription plans | Public plan GETs drop `stripe_price_id` for non-admins and `commission_override` for visitors. |
| Reviews, paused services, unpublished services | Review create also runs `can_review()`; pausing needs ownership or admin; `wpss_can_view_unpublished_service()` keeps the author-or-admin rule. |

## LOW notes, accepted for 1.9.2

1. `mark-paid` accepts any `payment_method` slug (`sanitize_key`). An admin who records `stripe` with an invented transaction id would send a later refund down the Stripe path and see it fail. Admin only, documented as a label in the route description.
2. Named MySQL locks carry no table prefix (`wpss_publishing_{user}_{service}` in `ServiceWizard`, `wpss_pro_paypal_payout_batch` in Pro), so two sites on one database server share the name. The worst case is a "being published" or "batch running" refusal while the other site holds it. The wizard lock is released when the request's connection closes, as its comment says; WordPress does not use persistent connections.
3. `VendorSubscriptionService::is_live()` treats a cancelled row with no `current_period_end` as live. Only the Stripe cancel door reaches `schedule_cancel()`, and Stripe rows carry a period end from checkout and renewal, so a vendor cannot cause this. Local plans are cancelled at once through `cancel()`.
4. `InternalWalletProvider::write()` reports a duplicate `(reference_type, reference_id, type)` as success. Today its only callers are the admin credit and debit actions (nonce plus `manage_options`), which mint a fresh `wallet_adjustment` id under `FOR UPDATE`.

## Scanner-visible but safe

- `sql-direct-interpolated` (Free 33, Pro 14): prefixed table names, constants, and already prepared fragments. `OrdersListTable::order_type_sql()` nests a prepared fragment built from the `get_sub_order_types()` allowlist; `wpss_order_number_search_sql()` interpolates a column the plugin passes itself and binds the terms with `esc_like` and placeholders.
- `service-gallery.php` echoes `wp_oembed_get()`: provider markup, and the URL passes `wpss_is_supported_video_url()` on read and on write.
- `paginate_links` output in `notifications-list.php` and `PayoutsSettingsRenderer` passes `wp_kses_post`; the settings toast passes `wp_strip_all_tags` then `wp_json_encode`.
- `files-superglobal` (22) and `upload-no-filetype-check` (1): unchanged from 1.9.1, validated through `wp_check_filetype_and_ext` and the attachment handler.
- `nonce-only-auth`: each handler also checks capability or ownership.
